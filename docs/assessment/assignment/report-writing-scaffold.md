---
title: Report writing scaffold
description: Turn the report rubric into a clear outline with prompts for evidence, design, reflection, and presentation.
---

This scaffold translates the four report criteria into planning questions and a copyable outline. It is a guide, not a required report format; use evidence from your own project and remove prompts that do not apply.

> **Report what you built.** Distinguish completed features from planned work. Explain limits and incomplete features directly.

## Plan evidence for each criterion

Use the evidence column to decide what diagrams, test results, examples, or sources you need before drafting.

<table>

  </thead>
  <tbody>
    <tr>
      <td>Objective, scope, and program features</td>
      <td>Who needs the program? What problem does it address? What did you include, exclude, and implement?</td>

    </tr>
    <tr>
      <td>Design and reasoning</td>
      <td>How do the modules and data flow fit together? Why did you choose this design? Which alternatives did you consider?</td>

    </tr>
    <tr>
      <td>Critical thinking</td>

## Copyable outline

Replace each prompt with project-specific details. Support important claims with results or examples, then explain what the evidence shows.

```markdown
# 1. Objective, scope, and features

- Intended user and problem:
- Project objective:
- In scope / out of scope:
- Implemented features and evidence:

# 2. Design and reasoning

- Chosen architecture and algorithms:
- Module responsibilities and data flow:
- Alternatives considered:
- Benefits, trade-offs, and reason for the final choice:

# 3. Implementation and results

- Important implementation decisions:
- How each key feature was tested:
- Results and remaining limitations:

# 4. Critical reflection

- Problem and impact:
- Response or fix:
- Evidence that the response worked:
- Alternative considered and why it was not chosen:

# 5. Conclusion and references

- What objective was achieved:
- Most important limitation or next step:
- Sources cited in the report:
```

## Make the reasoning visible

For each important decision or result, connect the claim to evidence and then explain its meaning. A diagram should show how parts depend on one another; refer to it in the text and explain what the reader should notice.

| Claim                           | Evidence                                           | Explanation                                     |
| ------------------------------- | -------------------------------------------------- | ----------------------------------------------- |
| What did you decide or achieve? | What test, result, source, or diagram supports it? | Why does that evidence matter to the objective? |
