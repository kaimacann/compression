## Get started

The repository provides a C11 command-line tool for lossless byte archiving, restoration, inspection, search, and PNG/JPEG/PDF image processing. Byte archives use the project-specific `TCMP` v1 container. Media vectorization is intentionally aggressive and tuned for Terra's simple, low-detail, single-ink sketch use; it is lossy and is not general-purpose image compression. Keep the source image when detail or colour fidelity matters. Continue to [File handling](./guide/file-handling/) for format boundaries, or [Reference and troubleshooting](./guide/reference/) for commands and diagnostics.

:::warning[Data and security boundary] The executable does not encrypt files. `TCMP` is a learning-project format, not a security, backup, or general interchange format. Vector mode discards image information for Terra-style sketches and is not a general-purpose image compressor. Keep source files and use copies for experiments. :::

## Run a complete round trip

The output paths must not already exist. A temporary directory keeps the example's outputs separate from the repository and avoids replacing files.

<Code language='bash'>{`work_dir=$(mktemp -d)
./dist/bin/compression-demo compress samples/sample.txt "$work_dir/sample.tcmp"
./dist/bin/compression-demo decompress "$work_dir/sample.tcmp" "$work_dir/sample-restored.txt"
cmp samples/sample.txt "$work_dir/sample-restored.txt"
rm -r "$work_dir"`}</Code>

The `cmp` command prints nothing and returns success when the restored bytes are identical. For a small or incompressible input, `TCMP` may use a raw frame, which preserves the bytes but adds container overhead. The format and its limits are described in [File handling](./guide/file-handling/).

## Use the command-line modes

Pass paths as separate arguments. Quote paths that contain spaces. The process returns status `0` on success and a non-zero status when an argument, input, container, or output operation fails.

<Code language='text'>{`compression-demo compress <input> <output.tcmp>
compression-demo decompress <input.tcmp> <output>
compression-demo inspect <input>
compression-demo search <input> <literal-text>
compression-demo --help`}</Code>

The interactive menu opened by `make run` or `./dist/bin/compression-demo` supports archive compression, decompression, and exit. Use command-line modes for `inspect` and `search`: `inspect` reports byte frequencies in sorted order, while `search` uses Knuth–Morris–Pratt and prints up to the first 20 zero-based match offsets.

### Examples

Use new destination paths for each run. The compression command leaves its source file unchanged.

<Code language='bash'>{`./dist/bin/compression-demo compress "samples/sample.txt" "sample.tcmp"
./dist/bin/compression-demo decompress "sample.tcmp" "sample-restored.txt"
./dist/bin/compression-demo inspect "samples/sample.txt"
./dist/bin/compression-demo search "samples/sample.txt" "compression"`}</Code>

## Process PNG, JPEG, and PDF images

`process` checks file signatures, so the extension does not determine the format. Lossless mode validates PNG/JPEG input and copies it unchanged. Vector mode decodes PNG or JPEG pixels, quantizes colours, traces SVG paths, and writes an SVG. For PDFs, it processes supported embedded image objects, exports SVG sidecars, and keeps the rebuilt PDF only when it is valid and smaller. Unsupported PDF objects remain in the copied or rebuilt document and are reported.

<Code language='bash'>{`./dist/bin/compression-demo process samples/bald.png bald.svg --mode vector --colors 32 --tolerance 0.5
./dist/bin/compression-demo process samples/image-stream.pdf vectorized.pdf --mode vector --svg-dir vector-images`}</Code>

Use `--force` only when replacing existing output paths is intentional. Create the `--svg-dir` directory before running the command. The default palette is 16 colours and contour tolerance is 0.5 pixels; allowed values are 2–256 colours and 0–2 pixels. Vectorization changes image appearance, and an SVG may be larger than its raster source.
