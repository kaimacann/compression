## Command reference

Run the executable from the repository root or provide paths relative to the current directory. Quote paths containing spaces.

| Command                                                        | Behaviour                                               |
| -------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `./dist/bin/compression-demo compress {''} {''}`               | Write a raw or Huffman `TCMP` v1 frame.                 |
| `./dist/bin/compression-demo decompress {''} {''}`             | Validate and restore bytes from a `TCMP` frame.         |
| `./dist/bin/compression-demo inspect {''}`                     | Report file size and the ten most frequent byte values. |
| `./dist/bin/compression-demo search {''} {''}`                 | Search literal bytes and print matching offsets.        |
| `./dist/bin/compression-demo process {''} {''} --mode lossless | vector [options]`                                       | Validate PNG/JPEG/PDF input; vector mode writes SVG output and supported PDF image replacements. |
| `./dist/bin/compression-demo --help`                           | Print command syntax.                                   |
| `./dist/bin/compression-demo`                                  | Start the interactive menu.                             |

Process options are `--svg-dir <directory>`, `--colors 2..256`, `--tolerance 0..2`, and `--force`. The `--svg-dir` directory must already exist. Existing outputs are rejected unless `--force` is supplied to `process`.

Vector mode defaults to two palette colours and a one-pixel contour tolerance. This intentionally aggressive setting targets simple, low-detail Terra sketches; it is lossy, may remove meaningful features, and is not general-purpose image compression. Keep the original when fidelity matters. PDF processing writes a rebuilt PDF when the candidate is smaller and exports embedded images as SVG sidecars.

The program exits with status `0` after success and `1` after an operation or syntax failure.

## Build targets

| Make target             | Behaviour                                                                       |
| ----------------------- | ------------------------------------------------------------------------------- |
| `make`                  | Build with the configured C11 compiler and warning flags.                       |
| `make run`              | Build if needed, then start the interactive menu.                               |
| `make clean`            | Remove the executable and analyzer output under \`dist/cache/clang-analyzer/\`. |
| `make check-doc-params` | List documented C functions that lack `@param` tags.                            |

The default build uses only the permitted standard C headers `stdio.h`, `stdlib.h`, `string.h`, and `math.h`. It has no third-party C dependencies. The implementation uses the C11 `fopen` exclusive-create mode for output safety.

## Public C interface

`src/c/compression/compression.h` provides the path-based operations. Each function returns `1` on success and `0` on failure.

```c
int archiveFile(const char *inputPath, const char *outputPath);
int decompressFile(const char *inputPath, const char *outputPath);
int inspectFile(const char *inputPath);
int searchFile(const char *inputPath, const char *pattern);
int processMedia(const char *inputPath, const char *outputPath, const MediaOptions *options);
```

The compression module owns file streams, `TCMP` framing, and the Huffman tree. Media staging and PDF/image processing live under `src/c/compression/`. The interactive and command-line interfaces are in `src/c/main/main.c`.

## Troubleshooting

| Symptom                                                                 | Resolution                                                                                                        |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `cc` or `make` is not found                                             | Install the platform's C toolchain and Make. If needed, select another compiler with `make CC=clang`.             |
| Input cannot be opened                                                  | Check the path, current directory, file permissions, and whether the file exists.                                 |
| Output already exists                                                   | Choose another destination or remove the old output yourself. The program does not overwrite files.               |
| `Input is not a valid or supported TCMP v1 file`                        | Check that the input is a complete `TCMP` v1 output; other compression formats are unsupported.                   |
| Payload is truncated, corrupt, has trailing data, or fails its checksum | Recreate the container from the original input. The stored FNV-1a value is not cryptographic authentication.      |
| `make` reports no rule or an unexpected target                          | Run Make from the repository root and check that `Makefile` is present.                                           |
| Docs commands are missing                                               | Run `pnpm install --frozen-lockfile` and check the Node.js and pnpm versions in the [getting started guide](../). |

## Supported behaviour

| Area | Current behaviour |
| --- | --- |
| Input | Archive commands read opaque bytes; `process` detects PNG, JPEG, and PDF from signatures. |
| Compression | Deterministic Huffman coding when its complete frame is smaller than the raw frame; otherwise raw framing. |
| Decompression | Raw and Huffman `TCMP` v1 frames, with declared-size, frequency, and FNV-1a checksum validation. |
| Inspection | Byte count and sorted byte-frequency summary. |
| Search | Literal byte sequence search with Knuth–Morris–Pratt; no semantic document parsing. |
| Output | New file only; existing destinations are rejected; incomplete outputs are removed after detected failures when the filesystem permits. |
| Login and archive encryption | Login gates menu and command use. Ordinary-file TCMP archives are encrypted after archiving and decrypted for restoration; the archive is then re-encrypted. Coursework-only implementation: plaintext passwords and fixed-key XOR are not production security. |
| Raster images | PNG and baseline/progressive JPEG decode to RGBA; vector mode quantizes and traces them to SVG. |
| PDF | Vector mode processes supported embedded image streams, exports SVG sidecars, preserves other page objects, and selects a rebuilt PDF only when smaller. Unsupported objects are retained and reported. |
| Interoperability | `TCMP` is private to this repository and is not ZIP, gzip, zlib, or a published standard. |
