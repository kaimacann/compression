## Command reference

Run the executable from the repository root or provide paths relative to the current directory. Quote paths containing spaces.

			</td>

		</tr>
	</tbody>

Process options are `--svg-dir <directory>`, `--colors 2..256`, `--tolerance 0..2`, and `--force`. The `--svg-dir` directory must already exist. Existing outputs are rejected unless `--force` is supplied to `process`.

Vector mode defaults to two palette colours and a one-pixel contour tolerance. This intentionally aggressive setting targets simple, low-detail Terra sketches; it is lossy, may remove meaningful features, and is not general-purpose image compression. Keep the original when fidelity matters. PDF processing writes a rebuilt PDF when the candidate is smaller and exports embedded images as SVG sidecars.

The program exits with status `0` after success and `1` after an operation or syntax failure.

The default build uses only the permitted standard C headers `stdio.h`, `stdlib.h`, `string.h`, and `math.h`. It has no third-party C dependencies. The implementation uses the C11 `fopen` exclusive-create mode for output safety.

## Public C interface

`src/c/compression/compression.h` provides the path-based operations. Each function returns `1` on success and `0` on failure.

<Code language='c'>{`int archiveFile(const char *inputPath, const char *outputPath);
int decompressFile(const char *inputPath, const char *outputPath);
int inspectFile(const char *inputPath);
int searchFile(const char *inputPath, const char *pattern);
int processMedia(const char *inputPath, const char *outputPath, const MediaOptions *options);`}</Code>

The compression module owns file streams, `TCMP` framing, and the Huffman tree. Media staging and PDF/image processing live under `src/c/compression/`. The interactive and command-line interfaces are in `src/c/main/main.c`.

## Troubleshooting

<table>
	<thead>
		<tr>
			<th>Symptom</th>
			<th>Resolution</th>
		</tr>
	</thead>
	<tbody>
		<tr>
			<td>
				<code>cc</code> or <code>make</code> is not found
			</td>
			<td>
				Install the platform's C toolchain and Make. If needed, select another compiler with <code>make CC=clang</code>.
			</td>
		</tr>
		<tr>
			<td>Input cannot be opened</td>
			<td>Check the path, current directory, file permissions, and whether the file exists.</td>
		</tr>
		<tr>
			<td>Output already exists</td>
			<td>Choose another destination or remove the old output yourself. The program does not overwrite files.</td>
		</tr>
		<tr>
			<td>
				<code>Input is not a valid or supported TCMP v1 file</code>
			</td>
			<td>
				Check that the input is a complete <code>TCMP</code> v1 output; other compression formats are unsupported.
			</td>
		</tr>
		<tr>
			<td>Payload is truncated, corrupt, has trailing data, or fails its checksum</td>
			<td>Recreate the container from the original input. The stored FNV-1a value is not cryptographic authentication.</td>
		</tr>
		<tr>
			<td>
				<code>make</code> reports no rule or an unexpected target
			</td>
			<td>
				Run Make from the repository root and check that <code>Makefile</code> is present.
			</td>
		</tr>
		<tr>
			<td>Docs commands are missing</td>
			<td>
				Run <code>pnpm install --frozen-lockfile</code> and check the Node.js and pnpm versions in the <a href='../'>getting started guide</a>.
			</td>
		</tr>
	</tbody>
</table>

## Supported behaviour

<table>
	<thead>
		<tr>
			<th>Area</th>
			<th>Current behaviour</th>
		</tr>
	</thead>
	<tbody>
		<tr>
			<td>Input</td>
			<td>
				Archive commands read opaque bytes; <code>process</code> detects PNG, JPEG, and PDF from signatures.
			</td>
		</tr>
		<tr>
			<td>Compression</td>
			<td>Deterministic Huffman coding when its complete frame is smaller than the raw frame; otherwise raw framing.</td>
		</tr>
		<tr>
			<td>Decompression</td>
			<td>
				Raw and Huffman <code>TCMP</code> v1 frames, with declared-size, frequency, and FNV-1a checksum validation.
			</td>
		</tr>
		<tr>
			<td>Inspection</td>
			<td>Byte count and sorted byte-frequency summary.</td>
		</tr>
		<tr>
			<td>Search</td>
			<td>Literal byte sequence search with Knuth–Morris–Pratt; no semantic document parsing.</td>
		</tr>
		<tr>
			<td>Output</td>
			<td>New file only; existing destinations are rejected; incomplete outputs are removed after detected failures when the filesystem permits.</td>
		</tr>
		<tr>
			<td>Login and archive encryption</td>
			<td>
				Login gates menu and command use. Ordinary-file TCMP archives are encrypted after archiving and decrypted for restoration; the archive is then re-encrypted. Coursework-only implementation:
				plaintext passwords and fixed-key XOR are not production security.
			</td>
		</tr>
		<tr>
			<td>Raster images</td>
			<td>PNG and baseline/progressive JPEG decode to RGBA; vector mode quantizes and traces them to SVG.</td>
		</tr>
		<tr>
			<td>PDF</td>
			<td>
				Vector mode processes supported embedded image streams, exports SVG sidecars, preserves other page objects, and selects a rebuilt PDF only when smaller. Unsupported objects are retained and
				reported.
			</td>
		</tr>
		<tr>
			<td>Interoperability</td>
			<td>
				<code>TCMP</code> is private to this repository and is not ZIP, gzip, zlib, or a published standard.
			</td>
		</tr>
	</tbody>
</table>
